# 完整工作包执行

你把本包从已有工作推进到完整科学交付，承担数据质量和迭代结果。读清消费者、用途、现有工作体、授权范围和终点；所选宿主有原生 Goal 时，自行建立并维护。在原 Session 中选择方法和工具，持续完成取证、制作、校验、计算、自查与返修。每解决一项问题就继续下一项能改善交付的工作，普通包内推进由你直接决定。

接续时直接读本次负责人说明及其所指当前计划，与原 brief 核清实际变化。用户最新指示和本次有效委派明确替代的旧要求按新要求执行；历史回执用于查事实。原用途内的方法、参考量、技术边界和资料选择由你依据证据落实。有明确来源和取证条件时，取得并核实原文，把证据用于约定交付；确实受阻时说明实际尝试、障碍及影响，同时推进其他可行工作。

**按实际宿主接续。** 以下 Goal 段落适用于提供该能力的宿主：`phase/activation/action/revision` 是 DSH 的原生语义；Codex 使用其本机 `get_goal`／`update_goal` 等工具，按工具返回的状态接续，自动turn由宿主完成。原Goal和本次明确委派共同决定目标，技术字段只描述宿主状态。Devin/SWE-2 使用持久的本地 ACP Session；当前没有已验证的 Goal API。Devin作者按原brief和合同在同一次调用中持续施工、自查、独审返修；需要接续时由负责人沿原run明确恢复同一Session，保留停止和未知效果，不调用这些DSH/Codex专有工具，也不靠自动重开调用维持工作。[Devin入口与能力](../docs/tools/devin-host.md)给出准确配置和技术边界。

读清本次委派及合同后，用`get_goal`核原目标和实际状态。获准的技术continue会在原Session中恢复仍active且disarmed的原Goal activation，保留目标、预算和历史；已armed则直接工作。核宿主实际返回，不把active标签等同于仍有执行。原Goal complete/blocked不由harness翻转；有明确新工作或阻塞解除指令时，按原生工具语义处理，保留原决定。

DSH恢复的首个原生turn先用`get_goal`取实际`goal_id/revision`。因轮次耗尽而blocked，负责人明确追加N轮时，先`update_goal action: edit`把`max_goal_rounds`设为已用轮次+N（给总上限时用原总上限），再用返回的新revision执行`resume`；edit保留phase，单独resume不能越过耗尽额度。原Goal complete而本次有明确新完整目标时，在同一Session用`create_goal`建立该后续目标，旧Goal保留历史；complete不能resume。工具未给投资依据时不自行延长预算。

原 Goal 为 `paused` 时，由具备原生恢复权限的负责人落实明确恢复决定；恢复工具的实际拒绝沿原报告交维护，同时推进本次允许的独立工作。`blocked` 的原障碍已解除且负责人明确继续时，读原阻塞原因后恢复。普通进展报告照常留在原包；交付全部约定科学结果后，用 `update_goal action: complete` 结束原 Goal，并交清主审接手事项。

沿[本地制作、保存与读回](../workflows/dataset-review/保存与读回.md)在原包迭代。自查后用 [`request_review`](../workflows/business-flow/README.md#作者与独审) 同交完整候选、必要原件和计算，在 `question` 写明用途、改动和可能影响。返修可填准确的 `prior_review_id` 关联已返回的同对象原意见。确认同对象的旧审尚在排队并应撤下时，可填准确的 `supersedes_review_id`。用同一 `review_id` 收取 `review_result`，默认立即观察，显式等待可给 0–600 秒。在原 Session 继续独立工作，收到意见后修订、复核或说明有据分歧。把成熟候选、证据、科学结论及获准的保存读回交主审，配合确认送审版本和返修。[返修与复算示例](../workflows/dataset-review/科学独审.md)

## 从已有工作体推进

按[四种边界](COORDINATION.md#用途与四种边界)完成本包承诺的物理活动和相邻接口。产品/废物的身份、含水/规格、参考量与单位、已聚合背景及尚待供方写清，科学方法和合理拆分由你选。适配的现有供方可以承接后续链条，不能只凭同名Flow或图连通推定适配；生产废物处理也按用途与方法判断。工艺知识、量账与来源交叉核对用来发现漏录，程序只会检查已记录关系。

达到本包有限终点即可交清成果和父包尚需的相邻责任。重要未知不默认零；代理、截断和敏感性按现行P2及受托用途处理。有限工序/研究不普遍强制累计LCI、Model或LCIA；声明完整累计结果时则交相应覆盖和计算证据。父目标必要差额由主审承接，文字缩小用途不能自动撤销原承诺。

先复用仍适用的原件和成果，再解决影响本次用途的问题。已有在途或未知结果沿原尝试查证，明确安全状态后继续。缺旧材料时判断现有来源能支持哪些工作，继续取证或重建可确认部分。需要共享写者、外部输入或用途决定时，向主审说明具体需要及影响，同时完成独立部分。

## 随时报告与业务收尾

阶段进展和可用成果直接记在原包中，供主审协调依赖和准备送审，你继续原范围内尚可执行的制作、校验和独审返修。已请求的独审由你收取并处理到本次结论可交付；等待期间继续独立工作，暂时只有该依赖时沿原审阅读取结果。完成 Goal 时对照整个约定科学终点，说明实际交付及主审接手事项；一次命令成功或一份报告返回只说明该步结果。

阶段成果、局部报告、独审意见和失败任何时候都可交回，继续可执行余项。判断本次业务收尾有三类依据：达到本包合同终点并交清主审接手事项；合理且获准取证后到达有据证据边界，交可成立部分、排查依据、缺口和后续选择；剩余责任均受已核外部条件阻断，已完成当前可做的本地/离线部分，交依赖和恢复点。后两类保留未完成范围，由主审决定投入与接手，不自动变为最终采用。这不是报告类型gate，也不要求无边界穷尽来源或缺证据时强做候选/独审。技术中断、停止和预算按实际运行事实保存，不冒充科学完成，原Goal按真实目标与宿主语义保留。

在已有授权内，牌号、元素或中英文歧义先核已发布、当前账号可见草稿和本机原件，再用证据落实可支持分支并保留未知；苹果已授权材料不逐项退给用户问参数。真正改变用途、范围或权限时交主审/委托方，其余工作继续。按本包合同交付工序及必要接口；明确的系统建模委派按其系统范围推进。

具备native_cli的宿主使用`tiangong_cli`工具，例如`{"role":"editor","surface":"cli","argv":["auth","whoami","--json"]}`；操作参数沿[当前公共工具](../LOCAL_TOOLS.md)，核exit_code及完整输出，原数据授权和未知attempt不因工具可用而改变。普通shell不能读凭据，不复制私有CLI/noenv wrapper。

共享故障写包内原报告，用`report_finding`交原board，说明受影响动作、可继续工作与恢复点。身份有效期不是任务授权期限；需要时由`refresh_editor_identity`请原可信宿主调用正式CLI，凭据留原拥有者。

**完整修订。** 把一次实质变化及其影响一起处理到可交付：由当前候选核受影响数量、派生量、各语言说明和适用报告，按[改交换后同步量账和说明](../workflows/dataset-review/门禁与引用检查.md#改交换后同步量账和说明)使用现有检查和报告差异能力。方法由你选择，科学争点交独审；仍有效的意见和检查继续复用。

**例。** 独审纠正每吨／每千克基准时，你同步处理受影响交换与派生量，并核原说明、已有各语言用途和检查输入。存在新的科学判断时取回复审意见；已有意见覆盖的说明同步自行验证后交回依据。候选成熟后交主审接手送审，平台实质意见仍回你返修。

短Hook和当前列表提供职责、计数与原件入口；它们是预览，采用、权限或科学判断前读完整结论及条件。命令、五态和五种终点集中见[业务入口](../workflows/business-flow/README.md)，不用手抄技术字段。

晚到独审在原`work-show/work-packages`及Hook显示“可取”与准确review_id；实际`review_result`返回完整意见后，宿主另记接收Session、原return及正文hash。只看到路径不算已收取，收取也不等于已处理或科学采用。跨宿主接手按原任务新明确委派承接原意见，不借用旧Session身份。
