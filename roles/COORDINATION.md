# 责任、派工与交接

每人从同一工作区打开原委派、所需原件和最近决定。给下一位说清他接的是哪件事、谁会用、在什么条件下能交付。

## 用途与四种边界

| 决定 | 谁负责 |
| --- | --- |
| 数据库这版要覆盖哪些产品、技术、地区和时期 | 总主用产业证据和现库覆盖决定投入，向委托方解释取舍。 |
| 模型为哪种核算或比较服务，活动追到哪里 | 系统负责人和作者据用途、数据及方法判断。 |
| 某个过程包括哪些工序、参考产品和已有背景 | 作者说明核算依据，独审核实，主审按实际用途采用。 |
| 这个包承诺什么、交给谁、获准做哪些操作 | 委派者明确终点，主审安排整包。改变承诺回到原委派者。 |

派工复用父委派已有的依据，说明本次责任和上下游接入所需的规格、单位与边界。一个子包交付后，主审继续负责父包欠下的结果。[登记范围与合同](../workflows/business-flow/README.md#登记范围与一份合同)

## 作者、独审与主审

作者选择方法、制作、自查，向独立只读的审阅者提供准确候选和科学问题。同模型家族可以独审。审阅者直接把原文和证据交作者；作者修正、复算或解释分歧。主审决定哪个准确版本可用于什么目的，安排未完成项，并为已获准的正式送审取得回执。平台后续意见由[轮询维护者](platform-feedback.md)归集。[三种交接示例](../workflows/dataset-review/reply-templates/交接示例.md)

## 运行与恢复

同一交付的实质返修沿原意见和原写者接续。彼此可独立交付的余项，按各自用途派给明确的作者。接手前查原停止决定、是否还有活跃写者、迟到的意见和远端效果。写入效果未知时从原 attempt 查证。由原责任人完成有权转交的部分，新写者使用本人的权限。[原生运行与恢复](../docs/tools/production-host.md) · [采用与完成](../workflows/business-flow/README.md#随时返回采用与完成)

## 共享依赖与维护

一个准确供方由一位写者维护。每个消费者分别核对版本、规格、单位、已含背景和适用限制，在自己的模型里验证。跨包时双方保留原始出处、负责人和接回点。只有依赖它的部分等候，其余照常推进。[系统规划](../workflows/dataset-review/system-planning.md)

共享故障由[维护者](maintainer.md)在原 board 修复并交实际使用者回验。主审在原计划保管有效安排，逐次执行和远端效果查原回执。
