# 工作区维护

变更共享代码、入口或引导时读取本文件。用户当前指示优先；本次工程沿[唯一重构计划](../docs/workspace/agent-autonomy-plan.md)，职责见[维护负责人](maintainer.md)。

基础设施支持agent在清楚、可恢复、可验收的范围内自主交付。范围、合同、集中检查和短Hook共用原账本与投影；程序核确定性事实和真实权限，agent负责科学方法、用途和投入。修负责模块及直接调用者，撤掉重复或失据的阻断，保留原事实与必要恢复。检查只在相应动作边界执行，查询与展示不产生执行权限。

维护引导时，以角色要交付的结果、可用能力、下一步选择和交接责任为主线。限制写明具体受影响的动作，并给出可行接续。用“worker 返回后主审如何推进余项”“候选成熟后谁完成送审”等实际场景核对入口，科学完成和业务取舍由 agent 判断。

各 agent 在同一正式工作目录读取原任务与职责。维护者亲自实施和集成；没有本次明确委派授权，不创建或唤起其他 agent。保留历史成果、身份、停止与未知尝试，不等于保留历史代码路径。退役入口从现役路由、文档、模板和测试一并移除；必要承接只做一次。

核实际公共入口及原阻断后续动作。验证报告区分本地测试、实际加载版本、宿主运行和业务回验；不要用测试数量、目录存在或提交代替完成。真实数据 schema、账号权限与原生写入合同仍归相应工具，工作区集中汇集原检查及回执，不另造一份科学判定。

目录保管和 Git 边界沿 [NAVIGATION](../NAVIGATION.md)，原包能承载就原址使用；人读操作说明在根 [README](../README.md)。计划及时记录完成证据、剩余问题和下一步，避免上下文刷新后重复施工。
