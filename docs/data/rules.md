# 科学数据规则

从原 brief 的用途、参考量和当前工作体开始。涉及候选研制、科学资格或数据动作时，直接读[现行数据原则与授权](README.md#现行数据原则)原文（也可用 `python3 bin/context.py --principles` 查询），并核具名范围和例外。

## 先确定正文、功能基准和依赖

1. 按[底稿选择](../../workflows/dataset-review/candidate-preparation.md#choose-the-current-working-body)对照适用线上正文、最后完整读回和已接受未保存的候选。以有据且与本次用途相符的工作体承接，保留原版本和已审覆盖。
2. 确定参考产品及来源分母，核规格、参考属性、单位、有效方向、内部循环和分配。Flow 按物理含义、规格、单位及用途选复用或研制。补产品／废物 Flow 属性时给出有据转换并保留原参考属性。基本流引用核物质、单位、介质及 Worker 有效方向，实际修订沿[具名权限](../../AGENTS.md#权限和恢复)。
3. 本轮只补影响约定用途的差额。共享供方和递归背景按[系统规划](../../workflows/dataset-review/system-planning.md#shared-product-boundary)分清可复用接口与本批前景。

## 按对象现状选择状态路线

| 对象现状 | 当前动作 |
|---|---|
| 本人活动草稿（state 0） | 原写者沿适配的固定 UUID 和版本修订，按允许阶段保存并完整读回。 |
| 已在审（state 20） | 有退回权限的人在原审核单操作。作者重新读取平台上该版本，确认已退回可编辑草稿，再修订。 |
| 已发布 | 科学变更沿适配的后继草稿及原发布目标。具名同版技术例外核原授权、合格入口、完整差异、独审和预期状态。 |
| Model 生成的 Process | 修改实际输入或 Model，再生成结果。核准确 Model／结果成员、正文及 `model_id`、`model_version`；按对应入口核计算、成组保存和送审。 |
| 状态未知、其他状态或已撤回 | 先查实际状态、写者及依赖，沿已发出的原尝试确认效果，再选择获准动作。 |

涉及修订、送审及 Model／结果 Process 时，按 `--policy-key data_lifecycle` 展开原决定和[生命周期合同](dataset-lifecycle.md)。

## 让字段保留科学含义

- 分别记录实测、固定假设和真实未知，说明来源覆盖、取值、范围和用途影响。公开正文承载科学解释，原审核、工作过程和内部路径归证据包。
- 年度量按 [P2 的字段路线](process-platform-fields.md#按实际路线选择年度表示)选择真实年量、固定披露假设或适用的参考量回退。用 Platform 原生表示保留年度数值和准确参考单位，方法字段说明期间、推导和限制。完整回验往返，并保留原生缺证信息。
- 新研制且任务或来源未指定委托方时用 **天工LCA数据团队**。需 Contact 时核精确身份、版本、正文、owner 和 state。原决定在项目进度发布原包的 `triage547-20261025/dispatch-20261025/commissioner-default-user-instruction-20261026.json`。
- [命名](naming.md)按四字段和参考产品检查。[分类目录](classification.md)按当前版本、主活动与完整层级选用，历史代码作有据映射。多语言标量每种语言保留一个完整节点，数值、单位和受约束字段沿所选 schema。

## 交付、科学独审与平台动作

- 先用[门禁与引用检查](../../workflows/dataset-review/门禁与引用检查.md)检查同一候选，再将用途、参考基准、关键交换、适用组分、模型连接、原件和报告交[科学独审](../../workflows/dataset-review/科学独审.md)。已有效的原报告与审阅随绑定复用，实质变化后复核受影响部分。
- 计算可解性、覆盖、背景与 CF、科学用途和发布资格各取实际证据。原 Calculator 按[固定输入方法](../../roles/calculator.md)接续。平台数据动作按原账号、对象、动作和写责核实际授权；`auth identity-receipt` 取真实项目、账号和角色。公开可见范围为 state 100–199，editor 按适用权限诊断自有 state 0。准确删除排除、私有陆良范围和历史只读例外沿 `.control/sources.json` 的原件。
- Foundry Task 沿其公共合同及原尝试推进。固定草稿修订使用适用[官方 Skill 与 CLI](../tools/data-cli.md#按工作选择技能)，按[保存与读回](../../workflows/dataset-review/保存与读回.md)核预检、保存和完整原生正文。主审接手成熟候选的[实际送审](../../workflows/dataset-review/送审准备与实际送审.md)，核提交状态、review ID、成员关系和正文差异；作者配合科学返修。阶段成果交回后，主审继续落实原目标的剩余交付。
