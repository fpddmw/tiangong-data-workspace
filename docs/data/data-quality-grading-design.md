# LCA 数据质量分级设计

> 版本 0.2 · 2026-11-12 · **状态：设计提案，尚未部署**
>
> 本文定义 LCA 数据"如何分级、分级用来做什么"。它不改变任何现有门禁、权限、审批、状态或原生写入，不产生线上操作，也不把历史 PASS 提升为当前资格。落地前，一切准入仍以[科学方法工作流](../../workflows/dataset-review/README.md)和当前绑定政策为准。

## 0.2 相对 0.1 的变更

1. 明确**三阶段架构**：authoring → review → calculation；平台只是发布与人工审核通道，本地闭环不依赖平台。
2. 主张阶梯删除 C5–C7，只保留 **C0–C4**；生命周期与计算各自成轴，不再混进质量等级。
3. 新增**阶段 2 审核员合同**：输入、输出、独立性定义、失败模式。
4. 新增**阶段 3 计算证据**与"质量缺口 × 计算贡献"的优化优先级。
5. 存储改为**本地正本、平台副本**；公开 `state 100` 并列展示 **AI 与人类两份评审记录**，各自标注来源。

## 0. 已确认的设计选择

| 项 | 决定 | 含义 |
|---|---|---|
| 阶段模型 | authoring / review / calculation | 三阶段本地闭环；平台只承载发布与人工审核 |
| 维度集 | ILCD/EF 6 维 | 技术、时间、地理代表性、完整性、精度、方法学适当性与一致性；沿用 schema 既有槽位 |
| 可见性 | 公开 `state 100` 也展示 | AI 与人类评审结果并列；AI 记录标注"机器评审"。平台 Contact 名中性（2026-11-12 决定），公开侧来源区分依赖本地记录 |
| 作用边界 | 只影响"可声明什么 / 可用于什么"，并指导下一轮迭代 | **不**影响保存、送审、审核、发布准入；不新增关卡 |
| 平台关系 | 质量体系平台无关 | 阶段 1–2 可完全在本地完成；上传发生在本地评审通过之后 |

## 1. 三阶段架构与平台位置

| 阶段 | 谁 | 产出 | 失败时 |
|---|---|---|---|
| 1 authoring | 编辑者（工具/CLI/skill） | 完整正文 + 自检 gate 记录 + 证据包 | 回 1 重做 |
| 2 review | 审核员（独立上下文，全部工具） | 重算结果 + DQR + 用途判定 + 缺口 | 回 1 返修 |
| 3 calculation | 计算方 | 矩阵求解、结果、覆盖、主导贡献 | 回 1 做第二轮优化 |
| 平台 | 人 | `state 0 → 20 → 100`，人工审核 | 不影响本地循环 |

两条必须写明的边界：

- **平台 `state 0` 的语义不变**：它仍是"可编辑草稿"。本地"已通过阶段 2"是本地记录里的独立事实，不借平台状态表达，也不要求平台改语义。
- **本地方案不依赖平台**：gate 记录、DQR、用途判定、计算证据全部可在本地产生和复核；上传只是把已评审的快照交出去。

## 2. 为什么分级不能按"轮次"

现状不是"过几轮就是几级"。A/B/C 是按**动作**分的轮次：A01–A13 准备候选，B01–B10 送审，C01 按原目标验收；`state_code` 0/20/100 是生命周期，不是质量。流程刻意把五类声明分开——已保存、科学合格、数值可解、覆盖完整、已发布（[WORKFLOW.md](../../roles/WORKFLOW.md)），并反复声明 20 不等于质量合格、局部 `accepted` 不能替代 A07（[科学方法入口](../../workflows/dataset-review/README.md)）。

因此需要分级，但分级对象不能是"第几轮"：

1. **轮次是过程事实，质量是科学判断。** 把"通过第一轮"读成"质量一级"，会让结构性通过、科学性未过的对象获得假信号。
2. **质量是多维的。** 技术代表性很好、时间代表性很差的数据很常见；单一等级只能靠平均分掩盖关键缺陷。
3. **单一等级会被反向利用。** 把完整用途悄悄收窄成"有限用途"就能升级，而原流程 R06 明令禁止这种做法（见[科学方法入口](../../workflows/dataset-review/README.md)）。

## 3. 现状测量（2026-11-10/11 快照，非当前在线状态）

### 3.1 公开面（2026-11-10 发布包，8831 行 process）

| 观察 | 数值 | 含义 |
|---|---|---|
| `state_code` | 100 → 6104；0 → 2727 | 公开对象是主要展示面 |
| review 类型 | Not reviewed 6132；Dependent internal 2345；Independent internal 163；Independent external 143 | **发布状态 ≠ 审核状态** |
| 含 DQR 的行 | 66（public）/ 73 条审核记录 | 公开面约 1.1% 有 DQR，其余只能显示"未评定" |
| 已填取值 | Fair 222；Good 114；Very good 7；Not evaluated 1 | 现有数据用的是分类档位，不是数字分 |
| 指标覆盖不均 | 六维各约 53–55 次，方法学一致性仅 20 次，Overall 55 次 | 必须同时记录覆盖率 |

标度已由 schema 固定：`ProcessReview.common:dataQualityIndicators` 的 `@name` 是 ILCD 六维加 `Overall quality`，`@value` 为 `Very good / Good / Fair / Poor / Very poor / Not evaluated / unknown / Not applicable`。分级复用该词表，不另造数字标度。

### 3.2 阶段 0 投影（582 目标，2026-11-11）

只读投影见[结果](../../materials/packages/electricity-2023-lowvoltage-climate-tidas-20261029/publication-feasibility-20261030/goal582-20261101/quality-projection-20261111/SUMMARY.md)：582 个目标中 state 0 = 344、state 20 = 236、台账缺失 2；**本轮可验证高于 C0 的为 0**（投影未重跑原生校验，C1 以上均为台账标签），可用 DQR 为 **0/582**；`label_ceiling` 与台账 `修订阶段` 严格一一映射。

三个直接结论：

- **标签不能当等级。** 一一映射意味着零新增信息；上线它只是把"已送审/可送审/异常"改写成 C 编号。
- **公开展示的默认状态是"未评定"。** 分级不能靠回填估算，只能在真实评审中产生。
- **分类会漂移。** 11-03 的 271 条缺陷分类中，45 条到 11-11 已进入审核；等级必须绑定正文哈希，失效即重算。

## 4. 设计约束

1. 不新增审批节点，不新增 reviewer→Root 签字链（见[科学方法入口](../../workflows/dataset-review/README.md)）。
2. 平台无关：阶段 1–2 与计算证据全部可在本地产生、复核、重算。
3. 本地正本、平台副本：质量记录以本地为准，平台字段是发布投影。
4. 不阻塞既有路径：`WORKING_DRAFT_ONLY` 草稿仍可保存；等级低不等于不能送审。
5. 不写 `state_code`，不新增数据库列或表，不手改原生记录。
6. 未知不是中间分：未评估写 `Not evaluated / unknown`，并计入覆盖率。
7. 等级绑定 `(uuid, version, content_hash, 声明用途, 标准/运行时版本)`；任一变化即失效或重算。

## 5. 五轴结构

| 轴 | 回答 | 取值 | 所有者 | 能否继承 |
|---|---|---|---|---|
| ① 生命周期 | 平台走到哪一步 | 本地 / 0 / 20 / 100（+撤回、删除） | 平台 | 只由原生状态决定 |
| ② 主张阶梯 | 本地可对外声明什么 | C0–C4，单调，最差项封顶 | 本地投影 | 按正文哈希重判 |
| ③ 质量剖面 | 对声明用途有多合适 | 6 维 + Overall，5 档 + 覆盖率 + 证据等级；AI/人类各自记录（可多份） | 审核员 | 未受影响维度可绑定复用 |
| ④ 计算状态 | 在哪个系统里能解、算出什么 | 未算 / 可解 / 部分覆盖 / 失败 + model + demand | 计算方 | 按模型与需求重算 |
| ⑤ 用途判定 | 能否用于这个用途 | `fit` / `fit_with_conditions` / `not_fit` | 消费方或协调者 | 随用途与证据重算 |

## 6. 主张阶梯（C0–C4）

| 级 | 名称 | 可声明什么 | 证据门 | 现有节点 | 封顶规则 |
|---|---|---|---|---|---|
| C0 | 本地候选 | 只有草稿，无对外声明 | — | R02–R04 | — |
| C1 | 结构通过 | 能按当前 schema 序列化 | SDK 严格校验 + schema | A04 | A04 fail → C0 |
| C2 | 引用闭合 | 引用与单位链可解析 | 精确 type/id/version + 单位链 | A06 | 缺失/不兼容 → C1 |
| C3 | 物理合理 | 数量关系说得通 | A07 质量平衡 `passed` 或 `not_applicable_verified` | A07 | fail/证据不足 → C2（**关键封顶**） |
| C4 | 质量已评述 | 代表性、完整性、精度已评并披露 | 至少一份阶段 2 评审记录含 DQR 剖面 | 阶段 2 | 无剖面 → C3 |

规则：

- **不跳级**；每级绑定同一正文哈希。
- **C3 是科学声明上限**：质量平衡未过，C4 不得成立，其他维度的高分不能抵消。
- 平台审核与发布**不在本阶梯内**：它们是轴①的事实，不是质量等级。审核通过不提升 C 级，C4 也不代表审核通过。
- 阶段 2 的评审记录可以是 AI 或人类产生；两者都使 C4 成立，但公开时必须标明来源（见第 11 节）。

## 7. 质量剖面

- 6 个 ILCD 维度，加审核人自愿给出的 `Overall quality`。
- 每个维度带三项伴随信息：**证据等级**（M 实测 / C 计算 / L 文献 / E 专家 / P 代理 / U 未知）、**评分依据定位**、**该维度的适用边界**。
- **覆盖率** = 已给出结论的维度数 / 7（`Not applicable` 也算已结论，但须有对象特定理由）。
- **Overall 不是总分**：它是审核人的整体判断，不得由六维平均或加权计算；与维度明显矛盾时标"需复核"，不得静默覆盖维度。
- **AI 与人类两份剖面不合并、不平均、不互相覆盖**；各自保留来源、时间、依据。

评分锚点（存储与展示只用词表，内部可按 1–5 排序）：

| 维度 | Very good | Fair | Very poor |
|---|---|---|---|
| 技术代表性 | 同工艺、同规模、同燃料/路线 | 同类但规模或配置不同 | 不同技术路线 |
| 地理代表性 | 同国家/电网/市场 | 同区域或可比经济体 | 无关区域或未知 |
| 时间代表性 | 与目标年差 ≤ 3 年 | 4–10 年 | > 15 年或年份未知 |
| 完整性 | 重要交换全覆盖，截断准则有据 | 主要交换覆盖，缺口已披露 | 重要交换缺失且未披露 |
| 精度 / 不确定性 | 实测或统计分布已知 | 工程计算或文献值 | 专家判断或代理值 |
| 方法学一致性 | 分配、边界、单位一致且有依据 | 有披露的偏差 | 未解释的不一致 |

`Good` / `Poor` 取相邻锚点之间；`Not applicable` 仅在有对象/边界特定理由并记录后使用。每个维度的评分必须能指回来源或推导位置；指不回去就是 `Not evaluated / unknown`。

## 8. 阶段 2：审核员合同

**定位**：独立判断者，不是复读机。对确定性检查它重跑；对不可重算的判断（DQR、质量平衡是否真成立、作者是否漏检）它给出有依据的结论。

### 8.1 输入

| 输入 | 必要性 | 说明 |
|---|---|---|
| 完整正文 + `content_hash` | 必需 | 只审冻结后的正文，不审会话里的草稿 |
| 作者的 gate 记录 | 必需 | 作为**待核对的声明**，不是证据 |
| 证据包与来源定位 | 必需 | 支持逐维度指回来源 |
| 声明用途 | 必需 | 质量只对用途有意义；缺失则 verdict 只能是 `undetermined` |
| 标准 / rubric 版本 | 必需 | 锚点与词表的版本，避免跨版本比较 |

作者的 gate 记录建议格式（声明，不是证据）：

```json
{"schema": "data-workspace.gate-claims.v1", "key": "process:uuid@version",
 "content_hash": "…",
 "claims": [{"gate": "A04", "result": "pass", "report_ref": "…", "checked_at": "…"}]}
```


### 8.2 输出

```json
{
  "schema": "data-workspace.review-record.v1",
  "key": "process:uuid@version",
  "content_hash": "…",
  "rubric": {"id": "ilcd-dqr", "version": "1"},
  "reviewer": {"kind": "ai|human", "id": "…", "skill_version": "…", "context": "independent-session"},
  "gates": [
    {"gate": "A04", "author_claim": "pass", "recomputed": "pass", "diff": false, "report_ref": "…"}
  ],
  "dqr": {
    "technological": "Fair", "time": "Poor", "geographical": "Fair",
    "completeness": "Good", "precision": "Fair", "methodological": "Good",
    "overall": null, "coverage": "6/7",
    "evidence": [{"dimension": "time", "tier": "L", "pointer": "…"}]
  },
  "verdict": "accept|accept_with_conditions|return",
  "gaps": ["A07 residual 1.8% without basis", "no target-year source"],
  "reviewed_at": "…",
  "inputs_sha256": ["…"]
}
```

schema 定义见 [`quality-grading/schemas`](quality-grading/schemas/review-record.v1.schema.json)；字段变更须升版本，不原地改语义。

四条输出规则：

1. **`recomputed` 与 `author_claim` 必须分开记录**；不一致时保留双方，不静默采信作者。
2. `verdict` 只对**声明用途**成立；不得写成"数据合格"。
3. `gaps` 必须可执行：指出缺什么证据、影响哪一维、回哪个节点。
4. 没有足够证据时写 `undetermined` 与具体缺口，不得给"默认 Fair"。

### 8.3 独立性

- **不同上下文**：独立 session / 身份，不读取作者的推理链、草稿过程或自我评价。
- **可读作者产物**：正文、gate 声明、证据包、声明用途——这些是被审对象，不是作者的辩护。
- **重跑优先于采信**：确定性检查由审核员自己跑；不能因作者"已通过"而跳过。
- **差异即记录**：审核员与作者结论不一致时，记录双方与依据，交回阶段 1 或标注条件接受，不得抹平。
- **同一模型的自我复核不算独立**：同一上下文、同一提示、同一会话的"再想一遍"不构成阶段 2。

### 8.4 失败模式

| 情况 | 处理 |
|---|---|
| 证据不足以下结论 | `undetermined` + 缺口清单，退回阶段 1 补证 |
| 正文在评审中变化 | 评审作废，重新冻结后重审 |
| 作者 gate 声明与重算冲突 | 记录 diff，按重算结果判定，退回修复 |
| 审核员无法访问必需来源 | 记录不可达范围，verdict 不得为 `accept` |

## 9. 阶段 3：计算证据

计算不是第五个等级，也不是"能算就对"。它证明三件事：**可解性、覆盖、量级合理性**；它不证明数据正确。

### 9.1 记录

```json
{
  "schema": "data-workspace.calculation-evidence.v1",
  "model": "uuid@version",
  "demand": {"functional_unit": "…", "amount": 1, "unit": "…", "impact_method": "…"},
  "solved": true,
  "coverage": {"cf_present": 12, "cf_missing": 1, "impact_categories": ["GWP", "…"]},
  "results": [{"impact": "GWP", "value": 1.23e-2, "unit": "kg CO2e"}],
  "contributors": [{"key": "process:…", "impact": "GWP", "share": 0.31}],
  "anomalies": ["negative exchange in …", "provider fallback to public …"],
  "runtime": {"engine": "…", "version": "…"},
  "computed_at": "…"
}
```

规则：

- **必须绑定 `model` 与 `demand`**。同一份数据在 A 模型可解、在 B 模型缺供方是常态；不写清系统的"能算"是假的全局声明。
- **贡献按 `(dataset, model, impact)` 记录**；一个数据集参与三个模型就有三条贡献，不合并。
- 计算成功不提升 C 级，也不改变 DQR；它只进入轴④与用途判定。
- 计算失败要区分：缺供方、缺 CF、单位/矩阵错误、结果异常。只有前两类是数据覆盖问题，后两类可能是数据或工具缺陷。

### 9.2 优化优先级

> **优先级 = 质量缺口 × 计算贡献**

- **质量缺口**：未达到声明用途阈值的维度数；C3 未过时额外 +1。未知维度不计为 0，而是使优先级 `undetermined`。
- **计算贡献**：该数据集在指定模型与影响类别中的贡献份额。
- 两者任一未知 → 输出 `undetermined (missing: …)`，不参与排序。
- 不同模型、不同影响类别的优先级不合并排序；各自列表，标明 model/impact。

这条公式把"持续降低重要决策中的数据不确定性"变成可执行动作：先修贡献大且缺口大的数据，而不是先修容易修的。

## 10. 用途适配

判定输入：声明用途 + 主张级别 + 剖面（AI/人类各自或并列）+ 覆盖率 + 供应/CF 覆盖（A08）+ 计算状态 + 生命周期。

建议初值（**待校准，不构成门禁**）：

| 用途类 | 最低主张 | 代表性约束 | 覆盖 |
|---|---|---|---|
| 内部热点筛查 / 背景清单 | C3 | 无硬阈值；必须如实披露已评定与未评定维度 | 不设门槛，未评定须显式 |
| 归因型产品 LCA 背景输入 | C4 | 技术、地理不差于 Good；时间、完整性不差于 Fair | 6/7 |
| 模型 / 系统计算输入 | C4 + 计算可解 | 同上 | 6/7 |
| 对外比较性论断 | C4 + 人工评审 | 技术、地理、完整性、Overall 不差于 Good；时间、精度不差于 Fair | 7/7 |

规则：用途判定只能引用与声明用途同版本的阈值；阈值变更不追溯改写历史判定。

## 11. 公开展示（`state_code = 100`）

1. **两份记录并列**：AI 评审与人类评审各自成块，不合并、不平均、不互相覆盖。
2. **AI 块 = `reviewer` 为 AI 的记录**：由于 Contact 名中性且描述不体现自动化（2026-11-12 决定），平台侧无法仅凭 Contact 判断来源。展示层只能读 `review` 区块时，会呈现为“天工审核”；“机器评审”标签依赖本地 `review-record` 或可读取的伴随信息。这是已接受的限制，不得反过来声称平台已区分人/机。
3. **人类块**：显示审核类型、时间、机构/审核人（可公开时）与指标；若人类审核未填指标，显示"人工评审未给出质量指标"，不得用 AI 值填充。
4. **空值**：两份都没有 → "未评定"；只有一份 → 显示该份并标明缺失的另一份。
5. **冲突**：AI 与人类结论不一致时并列显示并标"存在分歧"，不自动裁决、不取平均。
6. **不做排名**：不显示星级汇总、百分位、跨数据集排行榜；`Overall quality` 不单独作为"总分"。
7. **版本独立**：按 `uuid@version` 展示，不合并版本；旧版本保留其历史记录与时间。
8. **修订后重评**：正文或依赖变化后，旧记录标 `stale` 并保留；新评审形成新记录，不覆盖旧版本展示。

## 12. 存储与读回（本地正本）

| 层 | 位置 | 所有者 | 说明 |
|---|---|---|---|
| 质量正本 | 原包内 `review-record.v1.json`（`storage.py place --kind evidence`） | 阶段 2 审核员 | 绑定 `content_hash`，含 reviewer 来源与 gate diff |
| 作者 gate 声明 | 原包内 `gate-claims.json` | 阶段 1 编辑者 | 待核对，不是证据 |
| 计算证据 | 原包或计算 run 内 `calculation-evidence.v1.json` | 计算方 | 绑定 model + demand |
| 平台评审（人/AI） | `modellingAndValidation.validation.review` | 人类审核人或 AI 工具 Contact | `reviewer` 引用决定来源；同一区块可有多条 |
| 平台展示 | 数据集详情页 | 平台 | 只读；并列展示两份记录 |

五条硬规则：

1. **AI 记录写入同一 review 区块，但 `reviewer` 必须引用具名的 AI 审核工具 Contact**：不得借用人类审核人身份；展示层按 reviewer 引用解析“机器评审”标识。
2. 上传时只复制快照；本地记录继续演进，不因平台副本过期而失效。
3. 不新建表、不加列、不建第二套状态机。
4. 公开读回必须与本地正本一致；不一致以本地为准并标记差异。
5. 本项目目前**没有**部署评审器、展示代码或计算证据生成器；第 15 节才验证。

## 13. 防作弊硬规则

1. 硬门禁不可用分数抵消：A07 fail 不能被其他维度的高档救回。
2. 未评估必须写 `Not evaluated / unknown`，不得填默认 `Fair`。
3. 覆盖率为 0 的剖面不得用于任何用途判定。
4. AI 与人类记录不得平均、拼接或互相填充。
5. 保存、送审、发布、审核通过都不自动提升 C 级。
6. 计算成功不等于数据正确，不提升 C 级或 DQR。
7. 等级绑定声明用途；不得为升级而收窄用途。
8. 按 `(uuid, version, content_hash)` 计级，不按 UUID 或名称计级。
9. 禁止平均分、星级、百分位与跨对象排名。
10. `Overall quality` 不得覆盖维度事实；冲突即标"需复核"。
