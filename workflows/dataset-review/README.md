# 数据审查与修订方法

作者根据原 brief、完整候选、来源及实际工具报告决定研究、制作和修订顺序，在原 Session 中自主推进。以下文档说明科学检查与真实操作，不定义阶段状态机、返回格式或节点跳转。

## 按当前阶段读取

| 当前问题 | 原方法 |
|---|---|
| 身份、来源、参考量及用途 | [候选准备](candidate-preparation.md)、[数据规则](../../docs/data/rules.md) |
| 结构、单位及精确引用 | [机器与引用检查](门禁与引用检查.md)、[实际工具](../../docs/tools/data-cli.md) |
| 数量、边界及结论可信性 | [科学独审](科学独审.md) |
| 既有数据需全面重审 | [完整重审](已有草稿完整重审使用说明.md) |
| 找不到合适供方 | [缺供诊断](缺供诊断.md) |
| 保存、读取或未知效果 | [保存与读回](保存与读回.md) |
| 平台送审及意见 | [实际送审](送审准备与实际送审.md)、[平台意见](../business-flow/native-review.md) |
| 退役、替代或删除 | [数据生命周期](../../docs/data/dataset-lifecycle.md)、[实际维护工具](../../.agents/skills/dataset-rls-maintenance/SKILL.md) |

作者请求独审时给原候选和科学问题；独审独立读取原件、核实结论，原文意见直接返回作者。作者自行修订和复核，按原目标交付。主审接回阶段成果后继续落实整个任务余项，接手成熟候选的平台送审并保留回执。送审后意见由[轮询维护者](../../roles/platform-feedback.md)定期汇总给主审。共享故障沿原 board 交维护者。

需要说明意见、采用范围或投入取舍时，可参考[三个交接例子](reply-templates/交接示例.md)。

历史工具与平台源码核查在 [sources.json](sources.json)，只用于追溯当时结论；当前能力以实际安装和原生回执为准。旧流程生成器、结果码及守卫规格已退出当前入口，历史版本留在 Git 与原任务证据中。

接收候选、返修或交给下一岗时，读[本流程的交接说明](AGENTS.md)。
