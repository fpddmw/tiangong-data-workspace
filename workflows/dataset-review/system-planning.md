# 系统用途、依赖规划与诊断

当原任务已要求多包形成一个系统、处理具体供需连接或交付系统计算时，按实际问题选用本文的方法。数据库建设方向与工作包价值由[总主](../../roles/global-main.md)按用途、当前覆盖、可复用成果和能力增量判断；过程条目、供方连接及计算结果是相应论证的证据。已有完整过程包按原 brief、[执行指南](../../roles/data.md)和[当前科学步骤](README.md#按当前阶段读取)推进。

## 何时采用

开始或接续已约定的系统目标时，从原目标取用途、功能需求、时空和技术边界、整体验收及原方案。沿在途 Task／attempt 和原写者接续，按必要依赖安排后续包。存在选供、连接或结果疑问时做有界诊断；已有充分依据的工作直接推进。消费者采用和系统回验落实本任务的相应承诺。

## 有限交付与完成判定

- **工作包交付支持父目标。** 作者完成约定科学成果和获准的保存读回，主审接手平台送审及用途验收。阶段交付、证据边界或外部等待时，接回可用部分和具体缺口，主审据此安排剩余工作。部分计算包可按原约定交付结构或数值结果，系统负责人继续落实完整足迹所需条件。
- **落实约定的消费者连接。** 原任务要求消费者接入时，对合格供方核精确身份、所选正文和依赖、参考属性／单位及实际选择与权重。共享包达到自身终点后由原消费者完成采用。以可复用数据覆盖为交付目标的包按声明用途验收，尚无具名消费者不妨碍有据的建设与交付。
- **系统负责人核父目标。** 对系统承诺的范围及覆盖，核必要根对象、功能需求和边界、来源与假设、相关科学独审及适用 A07、实际采用、数值与复算证据、交付形态和使用限制。把证据系于同一基线。未核实的项保留恢复条件。有明确用途依据的不适用项说明原因。新计算、送审或产品用途沿各自终点，原冻结交付继续保留。

## 上游产品、共享与递归边界

先区分[数据库版本、产品系统、Process模块和工作包责任](../../roles/COORDINATION.md#用途与四种边界)，再按实际用途选择深度与广度。相容供方、基本流、功能交付位置或有据方法边界均可终止展开，不固定递归层数；循环按准确对象处理。覆盖组合按实际价值选择，工艺完整性仍对照原辅料、能源、水、公用工程、物流/损失、排放、治理、生产废物和联产品等核查。图连通只支持已有关系，不能独自发现漏录或证明同名粉体的含水/功能相容。

从消费者的实际产品／废物需求核物理身份、规格或相态、参考属性与单位、交付边界及适用时间地域。先判断复用、纠正接口、修订必要供方或确需新研制。铜粉、阴极铜和电缆铜棒各按实际物理身份选用。

在原消费者方案记录所需接口和返回点。复用已有适配的背景及原包。需要新作者材料时按 [NAVIGATION](../../docs/workspace/materials.md#topic-delivery-views) 放置。共享包在原入口记录已知消费者。接口、数量、参考单位、供方选择或依赖正文变动时，原写者交回影响，各消费者协调者按本用途复验。未受影响的冻结结果直接复用。

必要需求同时留在消费者原scope与interfaces/source_refs：准确供方或已核候选、缺的规格/数量/代表性、当前代理/未知、影响、写者与返回点。相容共享供方建设一次，各消费者单独采用；委派或board登记只记录责任，尚未满足接口继续算父用途差额。生产废物不因处理地点在厂外而天然排除；厂门产品也不要求穷尽其未来所有用途。供方更新只复验受影响的用途，案例年量或回退量不能自动作市场份额。

只展开会改变原验收的依赖。有限用途采用有依据的截断并披露影响。完整 LCI 保留缺失的必要上游和恢复条件。电力→铜→电力等循环按精确对象和接口去重，回同一系统模型分析选供、分配及可解性。

例如工段来源明确的代理投入按原证据纳入，投入品生产、残料处理及未知去向保留相邻接口。完整系统用途需要该依赖时，先核已有适配供方，再把会影响验收的缺口交主审排序。详见[原案例](../../docs/workspace/knowledge.md#原案例)。

## 项目自己的工作节奏

在原计划按[总主指南](../../roles/global-main.md)写明当前重点、优先级、已有授权、真实前置依赖和退出条件。安排能改变原验收、解除共享依赖或降低关键不确定性的工作。成熟包连续交付，可独立部分并行。计划更新跟随有意义的交付、依赖或验收变化。包的进展回原包，项目维护跨包决定。定时协调沿已有授权及实际宿主。

## 有界系统诊断

本节查明具体系统中的引用、选供、数量或结果疑问，为该系统的处理选择提供依据。发现质量问题后核其用途影响和原责任；是否需要扩大为建设包，回到总主的覆盖与投入判断。

1. **从一个具体疑问开始。** 从根过程和实际引用、选供或计算结果中找影响下一次选择的证据。按[当前底稿](candidate-preparation.md#choose-the-current-working-body)核精确版本和正文，标观察日期及覆盖限制。
2. **找出缺口属于哪一层。** 产品或废物交换需要供方时，先核端口含义、Flow 复用、引用、状态、单位、可见性和实际匹配规则。根据证据选择复用、纠正连接、修订供方、研制或进一步取证。查询未命中保留实际检索范围。基本流按其物质和环境交换角色处理。
3. **让计算回答具体问题。** 已有合格输入且结果会改变处理选择时，用 [Utilities](../../docs/tools/utilities.md) 适用的原生入口。当前受管离线分析有 `audit-loops` 和 `compare-results`。其他读取、重算或写入分别核资格和授权。绑定实际输入、方法、结果和适用范围。
4. **足以安排下一项就推进。** 说明必要工作、已有输入、实际消费者、处理选择及验收即可进入生产。有独立充分依据的包可以先做。关键输入缺失时，在原包写明需要核的证据、对哪项判断有影响和停止位置。完整矩阵和远期上游留给实际依赖与用途。

## 方案保留什么

用原计划或 brief 说明哪项验收还缺什么、当前基线及限制、为什么选择复用／修订／新建或研究、必要依赖与写者、下一批有限包及消费者回验位置。已有原件直接引用。没有可信贡献量时说明未知并给排序依据。新上游工作写明服务哪项尚缺验收和返回位置。

## 从方案到 Foundry Task

先查原 Task／attempt 和实际责任，复用符合条件的原任务。需要新建时，按当前 [原生启动合同](../../.agents/skills/foundry-tidas-import/references/task-workflow.md) 选 lane、输入和实际入口。source-evidence lane 需要位于 sources 中的已选 candidate seed。达到原生最小输入即可建立 Task，完整候选在相关写入前按工作包要求准备和独审。缺启动输入先取证，准确记录缺口和回原研制包的位置。

共享 Flow 的语义、参考单位和复用选择在原包确认，唯一写者沿实际入口固定身份。共用供方安排一次，消费者引用同一原包。先做真实前置依赖。独立部分继续。具体写责和宿主接续沿[协调合同](../../roles/COORDINATION.md)。

## 交付后怎样继续

有限包交回成果后，主审对照原目标安排余项：继续科学制作、接手平台送审、协调依赖或组织消费者验收。原作者仍有交付事项时沿原 Session 接续，已完成约定责任时明确结束该委派。证据边界由负责人判断后续投入，外部等待由其跟进恢复条件。消费者以实际选供及读取验证采用，系统负责人核父目标的整体覆盖与结果。影响下一项工作的缺口、假设或连接变化写回原方案和主题视图，未受影响的冻结成果继续复用。

以电力为例，固定原 2023 前景根和声明用途，沿实际引用定位必要问题。连接错就修连接，证据支持真缺供时研制必要供方。共享供方按各消费者的实际使用回验。当前阶段和证据沿[电力交付视图](../../docs/topics/electricity.md)读取。

## 原件与恢复

沿 [NAVIGATION](../../docs/workspace/materials.md) 复用原目标／brief 所属位置。原 brief 能说明上述内容时直接维护它。需要单独维护系统说明时放在原拥有者入口并链接。冻结请求、原生 Task 输入和历史回执按原绑定保留。

压缩或换会话后，从当前入口取原目标、原方案、准确 Task／attempt 和待用证据，先核当前责任与状态再决定下一项。计划保存实际判断和证据指针，运行事实向原拥有者读取。
