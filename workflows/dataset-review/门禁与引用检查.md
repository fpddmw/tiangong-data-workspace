# 机器与引用检查

对[选定完整候选](../../roles/CANDIDATE-PREPARATION.md#choose-the-current-working-body)及同批新改支撑运行适用的机器检查。先修确定性问题，把证据争点、当前正文和同一套报告一起交[科学独审](科学独审.md)。直接 CLI 与原 Foundry Task 分别按[实际绑定](../../LOCAL_TOOLS.md)使用原生入口。

## 用同一份输入检查

1. **检查结构与作者证据。** `dataset <type> validate --input /ABS/CONTENT.json --output /ABS/REPORT.json --json` 接受单个规范正文。逐项读完整报告的 schema、authoring_evidence、content、multilingual、allocation 等实际覆盖；完成执行与内容合格分别核实。TIDAS 包可沿 `validation run`，Model 正文用 `dataset model validate`，图操作另查当前帮助。
2. **检查交换和引用。** `list-references` 列出直接引用及路径，精确 `get` 取得 Flow、FlowProperty、UnitGroup 等正文。当前 Process business 检查按选定 Flow 完整名称核对每个交换；离线用 `--reference-documents` 提供精确正文，缺证据和名称不符分别读报告中的路径。用实际单位链和数量计算核量账；新版已退出旧 `qa process`，不假称具有其检查能力。引用资格与科学适配分别判断。
3. **区分本地与在线证据。** 新改支撑随整包进入独审；其保存鲜读后再核在线引用。在线检查显式选择 `validate --checks schema,business,references`。缺件或不可见标出准确路径，作者继续有证据支持的独立部分。
4. **看原报告和差异。** 数量、单位和派生值对应同一候选；检查结果仅覆盖实际运行的层。报告与候选的文件或载荷哈希对应后复用，科学意义由作者和独审对照来源判断。

## 改交换后同步量账和说明

数量、单位、方向或分母变了，作者围绕这项变化处理完整影响：从当前候选重算相关交换、派生量和总量，核对解释这些量的正文、表格、已有各语言说明及相关模型引用。按来源与合同解释 meanAmount、resultingAmount 和变量；工具能执行的算术使用实际计算结果，科学含义和双语等义由作者对照原文判断。原说明因变化失效时，以完整段落替换已失效的陈述，连同同段残留的旧说法一起核对；有长度限制时精炼句子，保留关键边界。

例如矿渣加工从每吨改为每千克，数值与派生字段一起核；加入燃气直排后，已有中英文说明明确所含排放及后续连接方式。保存读回验证存入内容与候选相等，作者另核候选内部的数量、说明和用途一致。用当前正文跑受影响检查，交付引用实际对应的报告；历史原件保留供查证。独审复核改变科学结论的部分，已有意见覆盖的说明同步由作者验证并说明依据。见[原案例](../../docs/workspace/knowledge.md#原案例)。

当前实测 CLI 0.4.0 仍会漏报无变量的 meanAmount／resultingAmount 冲突；问题交上游 [CLI #425](https://github.com/tiangong-lca/cli/issues/425)。修复采用前直接核这两个原字段及适用合同，不能用其零问题报告代替该关系核对。

## 标明哈希类型

核文件原字节时使用文件 SHA-256。核候选与实际保存正文时，先让两份正文使用同一投影和规范化，再比较载荷哈希。原生送审或批准校验和另按平台合同记录。返回时写明哈希对应的对象、版本、投影或文件，便于下一步选择原报告。

需复核实际文件与载荷时查[原案例](../../docs/workspace/knowledge.md#原案例)。

## 复用原包门禁

在仓库根运行，参数取原包和准确正文：

```sh
python3 -B bin/lca_gate.py --package ORIGINAL_PACKAGE --rows PROCESS_ROWS
```

按实际输入追加 `--reference-rows-file`（可重复）、`--support-rows`或 `--tidas-dir`。脚本可从原包、行所在的原生目录及可核 manifest 找引用正文。Model 正文作为支撑文件显式选择。报告分开记录真实失败、警告及未检查的范围，已有同输入、同组合的完整报告可复用。指定 `--out-dir` 用新目录；原失败先读路径，必要时 `--retry` 保留旧结果再执行。

`candidate-derived.md` 展示同一候选的交换方向、两种数量、精确 Flow、原生校验报告链接，供作者直接对照原文。已有 gate 报告时，可用下面的只读入口核其输入是否仍适用，并查看交换差异；它不重跑校验：

```sh
python3 -B bin/lca_gate.py --package ORIGINAL_PACKAGE --rows CURRENT_ROWS \
  --check-derived ORIGINAL_GATE_REPORT
```

`current` 表示该报告的输入仍相符；`stale` 时读实际差异，选择重跑受影响检查并更新原交付中的报告指针。`unverified` 会列出本次未核的依赖（例如原包外的文件），可沿报告中的准确路径和哈希查原件。数量没变而说明改了，仍由作者核说明与既有科学意见的关系。直接 CLI 的报告也可按其实际输入与正文哈希核对，无须为使用另一入口重建有效证据。

## 判断失败与交回

| 观察 | 处理 |
|---|---|
| 来源到字段映射、身份或参考量错误 | 修候选和受影响的量账；对准确修订稿重跑受影响检查。 |
| 适用检查漏跑、引用证据缺件 | 取得已支持的报告或原件，保留当前缺口，再集中交独审。 |
| 已固定候选触发工具冲突或能力缺失 | 按[原维护入口](../business-flow/README.md#维护发现的正常接续)保留原输入、运行时、失败及业务影响。候选正文仍以科学证据与实际平台合同为准。 |

在原包绑定候选、运行时、依赖、有效报告和剩余原生门禁；独审按[完整候选](科学独审.md)使用这些证据。

## 统一交接检查

用`.venv/bin/python bin/harness.py work-check --request ID --for handoff`汇集准确输入、原机器报告、科学意见及作者处理。未知、失败或未完分页只限制相应最终验收/写入，不阻止报告先入账。报告各自绑定实际输入和规则，不用全局CLI版本一概失效；纯排版变化有等义依据时沿用未受影响科学判断，不能证明则明确需复核。卡片和预览不参与完成或权限判断，完整来源通过`--output`或原报告读取。
