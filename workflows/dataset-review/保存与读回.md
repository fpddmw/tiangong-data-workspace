# 保存与读回

已有核准基线时，在原包起草本地副本。集中更新交换、受影响说明的全部语言、计算和自查报告。用 `request_review` 同交完整本地候选和相关既有计算，服务冻结所选文件。原包底稿保留修订过程，公开正文保留当前科学事实、来源和限制。已知量、分母、单位和限制沿原计算表或脚本的同一复算依据更新；派生数值、两语说明及用途条件有变化时一同核对。

用 `lca_gate.py --package DIR --rows CURRENT --baseline-rows ORIGINAL` 对照本次改动，或用 `--focus FOCUS.json` 选择报告要展开的字段。FOCUS 按 `process/UUID/VERSION` 写各根的 `exchanges`（交换 ID 字符串列表）和 `fields`（JSON Pointer 列表）。先读命令返回的 `summary`（`candidate-summary.md`），定位变化字段、选定交换数量及精确参考链；沿详细报告链接查看完整双语原文和结构值。共享 Flow 发生变化时，沿报告的消费者定位本组选定根，结合原包依赖确认全部影响。

同一口径写在多件正文时，可把独审指出的旧句或数值逐个定位到作者选定的 Process、Flow 和 Source 正文。例中 `OLD` 是待核原文，`FILES` 是这些 JSON 原件的路径数组。输出每个命中的文件、字段路径和语言；作者打开命中处与相邻语言，按原依据判断该数值在这里的含义。报告和交接说明中的同一句可用 `rg -n -F` 定位。

```sh
jq -c --arg old "$OLD" 'paths(strings) as $p | select(getpath($p) | contains($old)) | [input_filename, $p, (getpath($p[:-1]) | objects | .["@xml:lang"])]' "${FILES[@]}"
```

需要为下游提供持久对象、引用支撑已就绪或成熟稿需交接时，由原写者按下列原生合同核当前授权、精确对象和鲜读前像，预检、保存并完整读回。并发变化后重新核前像。效果未知沿原尝试查证。

## 选择适用的原生动作

| 当前对象 | 行动 |
|---|---|
| 已注册 Foundry 新研制／导入 | 沿原 Task 公共动作及当前门禁。现有 final_rows 写入合同为 Flow／Process／Source insert-only。 |
| 本人固定活动草稿或任务所需新草稿 | 新对象用 `dataset <type> create`，已有草稿用 `save`，读取当前动作的原生请求合同。 |
| Model 与结果 | 单件用 `dataset model create/save`。需要持久化整组时用 `dataset model result-group`，保存后独立 inspect，核完整 Model、结果 Process、revision 和成员关系。效果未知时按原 operationId 恢复。 |
| 公开对象科学变更、在审对象或技术例外 | 依[生命周期合同](../../docs/data/dataset-lifecycle.md)选标准后继、原审核退回或具名技术纠错。技术例外要实际合格入口、独立差异审查及适用的影响、前像和预期状态。 |

结构与引用诊断用本地校验、准确引用读取或同一请求的 `--dry-run`。对比变体放在原工作目录中，分别预演后比较错误路径和正文。正式 create 会生成真实草稿，用于委派内实际需要交付的对象和接口。

## 写前核当前前像及引用

准备执行合同的账号字段时，使用公开入口取得当前服务端核验身份：

```sh
python3 bin/launch.py --role editor cli auth whoami --json
```

标准回执中的 `context.actor.id` 与 `context.environment` 用于当前请求的 `expectedActor`／`expectedEnvironment`。准确账号可用显式 expected 参数核对；无需邮箱、JWT 或凭据解析。对象范围仍来自原任务授权。

1. 核实际账号、项目、原 owner／state、固定版本及完整鲜读前像，对照审定候选和适用授权。受管 Task 取当前原生 authorization、seal、readiness；相同正文重绑由原写者核原生报告。已有尝试消费时转读回；出现冲突时回[候选选择](candidate-preparation.md#choose-the-current-working-body)。
2. 新改支撑由原写者按各自实际入口先保存并读回。Process 的 Flow 和 Source 使用各自准确类型及动作表，先读回这些精确依赖，再核 Process 预检及在线引用可解析、资格和内容。例如本地新 Flow 可以先随整包独审，待其真实读回后方可绑定下游保存合同。
3. 对已有草稿，将完整候选和鲜读前像写入同一原生 save 请求，运行只读预检。它可以读取当前线上事实，使用已获准的账号；输出用原包下新报告目录。

```sh
python3 bin/launch.py --role editor cli dataset process save \
  --input /ABS/ORIGINAL/SAVE_REQUEST.json --dry-run --json
```

直接调用、其他对象和实际绑定见[本地工具](../../docs/tools/data-cli.md#账号保存与送审)。查看模式、已准备项、阻碍项及原生回执；`dry-run` 的 prepared／completed 只说明适用预检事实。

## 执行与验证

1. 原生请求含 `id`、`version`、`content`、稳定 `requestId` 及预期账号／环境；save 另含鲜读的完整 `expectedContent`。用精确原输入执行。CLI 在适用授权下对同次原生操作去掉 `--dry-run`，保留 native request／attempt 和报告。部分成功先查每项原效果。
2. 用正式读取接口鲜读完整正文及必要关系，比对候选与审定差异。核类型、UUID／版本、owner、预期 state、分类、年度量和引用。Model 同时核实际 result 组成员及 `model_id`、`model_version`；正文改变时重核相关计算输入。普通草稿期望 state 0；具名公开技术纠错按授权中的预期状态验收。
3. 将原执行、完整读回、科学用途和限制交回原请求。只读核验现有正文时照实记录实际读回。以草稿为终点的包按[原目标验收](methods.md#closeout)交付；主审接手获准的[实际送审](送审准备与实际送审.md)，作者配合提交版确认和科学返修。

## 具名停写及原尝试恢复

原包委派者或有权主审用 `work-decision-record --decision FILE` 登记原决定。设 `subject` 为 `dataset.remote_mutation`，`statement` 为 `stop` 或 `release`，`scope` 依次写准确 `task`、原 `package` 请求 ID、`object`（CLI 类型/UUID/版本）、`action`（`create`、`save` 或 `delete`）、项目 ref `project` 和在线用户 UUID `account`。`source_ref` 指向原决定的文件、哈希、定位及负责人。明确解除时用 `supersedes` 指定所替换的同范围原决定。用 `work-decisions` 带相同选择器核当前生效记录。

受控 CLI 在每次启动该原生变更前读取现行决定，并把已核的原始请求字节交给 CLI。停写、决定冲突或原决定来源不可核时，保留拒绝回执，读取与本地独审继续。已获准进入原生 CLI 的调用按原 attempt 查当前结果，停写生效即约束后续调用。

基本流、删除及可替换现存成员的 Model 结果组使用同一个决定入口登记有权人的原授权。选择 `dataset.remote_mutation.authorization` 和 `allow`，范围绑定当前任务、原包、准确对象、动作、项目与账号。组合保存的动作是 `result-group`。受控入口同时核拟写和原正文的 Flow 类别，原停写优先。普通自有活动草稿沿原 P4 和 CLI 校验。适用的 Model 结果组读取与恢复使用原 `inspect` 和 `recover`。

写入、送审／生命周期和删除结果未知时，取实际原生 handle、回执及适用鲜读，核该次操作的真实效果。保持原 writer、前像和请求身份。未确认效果的操作保留恢复条件；其余独立工作继续。鲜读受限且没有待判定写入时，补观察证据或交回可见性缺口。

受控入口按账号、环境和准确版本查 CLI 原写入 journal。已发出且未定的 dataset 操作暂缓同对象变更。使用新的请求号、Session 或工作目录仍沿原操作查证。正式拒绝或已确认成功由原操作终态结清。

CLI 对有较新发布版本的精确引用仍可能拒绝保存。保留原科学选择与候选，沿准确版本确认该次保存状态。可独立的候选按原授权和预检继续。[CLI #504](https://github.com/tiangong-lca/cli/issues/504)

## 接回终点依据

`work-check --request ID --for handoff`复用本次准确候选、原检查、独审处理及原生保存/完整读回。saved_draft要求原写入成功及准确对象、版本、正文的完整读回；截断JSON、投影正文、hasMore或未完分页均不作为完整读回。该查询不重放写入，不代替当前账号、项目、owner/state、前像与具名授权。身份需刷新或登录只暂停依赖身份的动作；原成果、本地制作及其他对象继续，OAuth有效期不等于工作授权期限。
