# Scientific Process review

Review the exact candidate and its original evidence. `run-review.mjs --profile process --input content.json --json` forwards typed validation; read the complete output and its actual coverage. It does not compute the former QA mass balance. Use exact get for remote snapshots and keep observed owner/state and available provenance separate from the scientific body.

- **Structure and contract:** use the installed Process schema, methodology and ruleset. Separate a missing required field from a scientifically inadequate explanation.
- **Purpose and reference:** establish the actual activity, functional unit, reference exchange and system boundary. Interpret normalization, allocation, services and aggregated results according to their evidence.
- **Names and classifications:** compare the Process, reference Flow and source terminology. Read the current contract and applicable naming rules; use the justified classification depth and complete path.
- **Exchanges and units:** trace each selected exact Flow through its property and unit, and check direction, quantity and physical meaning. An existing exact version is not invalid because a later one exists. Choose a revision only for a supported scientific reason, updating its description consistently.
- **Quantity consistency:** reconcile meanAmount/resultingAmount and variables; compute affected totals with actual unit conversions. Explain exclusions and uncertainties, rather than assuming a generic balance threshold certifies every process. Current CLI validation can miss the conflict documented in issue 425.
- **Representativeness:** assess technology, geography, time, annual production evidence, allocation, cutoffs and intended use. Keep unknown evidence explicit; a unit-normalized exchange does not establish annual production.
- **Complete revision:** compare the current quantitative result with all affected paragraphs, existing languages, tables, dependencies and report pointers. Changed boundary explanations replace obsolete statements as a whole. Check bilingual scientific equivalence directly.

Give the author substantive findings, evidence and their effect on the conclusion. Review consequential changes and reuse findings that remain valid. The author owns the candidate and iteration; the lead owns adoption and authorized submission. Return useful scientific feedback without requiring an extra directory structure, score or management form. Existing Foundry tasks keep their own original public actions and permissions.
